# 待确认问题与已知限制

> 本模块只实现已被明确要求的规则；下列业务口径**尚未冻结**，一律做成显式挂起 / 可配置但默认关闭。
> **业务规则以蒋的裁定为准，本版未擅自猜测。**

## 一、待确认问题（12 条）

### 1. 项目名称 / 材料名的传递口径
- 现状：`normalize_text()` 做 NFKC + 去空白标点 + 小写后比较，别名归一依赖 `item_catalog.aliases`；`material` 要求完全相等才算 exact。
- 需谁裁定：胡（识图输出规范）+ 蒋（是否允许材料名带品牌/规格前缀）。
- 若确认后改哪里：`quotation/models.py::normalize_text`、`quotation/matching.py::_find_exact_catalog`、`data/seed_prices.json` 的 aliases。

### 2. quantity.type 枚举与单位写法
- 现状：接受 `area/volume/length/count` 与中文；单位按映射表归一；未知 type/unit 进 `validation_errors` 并挂起。
- 需谁裁定：胡（是否再扩展枚举）+ 蒋（单位白名单是否冻结）。
- 若确认后改哪里：`quotation/models.py` 的 `QUANTITY_TYPES` / `_UNIT_MAP` 系列常量、`INTERFACE.md` 单位映射表。

### 3. 人工修改后打标方式（modified 是否可计价）
- 现状：`VALID_REVIEW_STATUS` 含 `modified`，但 `PRICING_REVIEW_STATUS` 只含 `confirmed`；`modified` 即使带 `modified_by` 也挂起并提示「打标口径待蒋确认」。
- 需谁裁定：蒋（modified + modified_by 是否等同 confirmed）。
- 若确认后改哪里：`quotation/models.py::is_review_usable_for_pricing`、`quotation/pricing.py::price_item` 第 2 分支。

### 4. 未确认工程量的处理
- 现状：`review_status != 'confirmed'` → `amount=None`、`needs_confirmation=True`、进 `pending_items`。
- 需谁裁定：蒋（是否允许「暂估工程量」参与参考计算）。
- 若确认后改哪里：`quotation/pricing.py::price_item`、`quotation/api.py::_build_pending_items`。

### 5. 工程量取整规则
- 现状：**未启用**，保留 `quantity_value` 原始精度（如 53.7812 不取整），`pricing_quantity` 同理。
- 需谁裁定：蒋（保留几位、何时取整、ROUND_HALF_UP 还是进一法）。
- 若确认后改哪里：`quotation/pricing.py::check_unit` / `calculate_amount`，`warnings` 文案。

### 6. 损耗系数
- 现状：**未启用**，无字段、不乘任何系数；`warnings` 明确提示待确认。
- 需谁裁定：蒋（按项目/材料配置还是全局、是否计入合价）。
- 若确认后改哪里：新增 `pricing_rules` 规则类型或 `quotation/pricing.py::price_item` 计算链。

### 7. 跨视图合并
- 现状：**未启用**，识图 items 逐条独立计价，同名/同部位不合并。
- 需谁裁定：胡（识图是否已合并）+ 蒋（合并键与工程量求和口径）。
- 若确认后改哪里：`quotation/api.py::generate_quote` 生成 rows 之前增加可配置合并步骤（默认关闭）。

### 8. 相似匹配阈值 0.60
- 现状：`FUZZY_THRESHOLD = 0.60`，`score = 0.7×名称最高相似度 + 0.3×材料相似度`，取 top3；仅参考价、不计入总价。
- 需谁裁定：蒋（阈值、权重、topN、是否允许 fuzzy 转正式价）。
- 若确认后改哪里：`quotation/models.py::FUZZY_THRESHOLD`、`quotation/matching.py::match_price`。

### 9. 同名多历史价取价策略
- 现状：`is_confirmed=1` 优先，再 `quote_date DESC, id DESC` 取最新；不覆盖旧价、不做均值/趋势。
- 需谁裁定：蒋（是否改为按项目来源加权、是否需有效期过滤）。
- 若确认后改哪里：`quotation/matching.py::_latest_price` 的 SQL ORDER BY。

### 10. 价格含税 / 币种 / 有效期口径
- 现状：`currency` 固定默认 `CNY`，无含税标记、无有效期字段；`quote_date` 仅作追溯。
- 需谁裁定：蒋（含税价/不含税价、多币种、价格失效规则）。
- 若确认后改哪里：`quotation/schema.sql` 的 `price_history` 增列 + `matching.py::_source_from_row` + `INTERFACE.md`。

### 11. 规格 spec 为空时的匹配口径
- 现状：空 spec 必须与 catalog 空 spec 才完全匹配；规格不同直接落到 fuzzy/none，不用「忽略规格」兜底。
- 需谁裁定：蒋（spec 为空是否允许忽略该维度）。
- 若确认后改哪里：`quotation/matching.py::_find_exact_catalog` 的 spec 比较。

### 12. 计数类单位之间是否可换算
- 现状：`个/套/件/项/台/樘/处/次/块` 同属 count 但默认不互通，只有 `pricing_rules.is_confirmed=1` 的规则才允许。
- 需谁裁定：蒋（哪些单位对允许、系数由谁确认）。
- 若确认后改哪里：`data/seed_prices.json` 的 rules、`quotation/pricing.py::check_unit`。

## 二、当前无法自动匹配或计算的情况（逐条）

| 触发条件 | 系统行为 | 需要人工做什么 |
|---|---|---|
| 无匹配（catalog 无对应项目/价格） | `match_status='none'`、`recommended_unit_price=None`、`amount=None`、`messages=["暂无可靠价格，等待人工填写"]`、进 pending_items | 报价员填写单价后 `update_quote_item_price` 或随 `confirm_quote(items=...)` 提交 |
| 相似匹配（score >= 0.60） | `match_status='fuzzy'`、给 top3 候选与 `provisional_amount`，`amount=None`、`needs_confirmation=True`、不计入 total_amount | 人工核对名称/材料/规格，确认参考价是否可用；不可直接采用 |
| 跨维度单位（如 m³ 对 元/㎡） | 直接拦截，`messages` 含「不属于同一维度，禁止直接相乘，请人工确认」，`amount=None` | 人工确认工程量维度或重新提供正确单位的工程量/价格 |
| 同维度但无已确认换算规则（如 cm→m 规则 is_confirmed=0） | 拦截，`messages` 含「换算规则未经确认，禁止换算，请人工确认」 | 由蒋确认规则并置 `is_confirmed=1`，或人工直接填写换算后工程量与单价 |
| 工程量未确认（review_status != confirmed） | `amount=None`、`messages` 含「工程量未经人工确认，暂不参与计价」 | 人工复核图纸工程量并置 `review_status='confirmed'` 后重新生成报价 |
| 识图校验失败（缺字段 / value 非数值或为负 / type、unit 未知 / review_status 非法） | 错误写入 `validation_errors` 与顶层 warnings，该行整体挂起，不参与计价 | 胡修正识图输出，或人工补录后重新调用 `generate_quote` |
| 同名历史价但计价单位不一致 | `match_status='none'` + `unit_mismatch`，candidates 列出其它单位历史价，**不自动推荐** | 人工确认或补充 `is_confirmed=1` 的换算规则；已确认规则命中时按同名历史价换算计价并标为 exact |
| `allow_unpriced=True` 的未计价行 | 允许确认，但该行 `final_unit_price=None`、不写入 `price_history`、不计入 total_amount | 后续单独补价并重新确认（注意本版禁止重复确认，需新报价单） |

## 三、结论
以上业务规则以蒋的裁定为准，本版未擅自猜测；代码均做**显式挂起**而非默认假设。
系统在任何不确定情况下都返回 `None` 价格 + `needs_confirmation=True` + 中文原因，
绝不生成、推算、插值或预测造价，也绝不把未确认价格写入正式历史价格库。
